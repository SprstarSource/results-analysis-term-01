# Test Plan

The toolkit has **no automated tests**. This plan defines how to verify it manually and with synthetic fixtures, so that every release and every behaviour change can be checked in a repeatable way. It covers the whole program as one system: the data-flow chain, the orientation chain, the analysis builders and the cross-cutting safety rules.

Expected results marked *(spec)* are derived from `ARCHITECTURE.md` and the module header comments. Where a case is marked **Explore**, the expected behaviour is not established by the code; the tester records what happens and opens an issue if it is wrong.

## 1. Objectives and scope

**Objectives**

1. No test run may ever modify, lose or corrupt a workbook it should not touch.
2. Orientation decisions match the documented rules for every input, including boundaries.
3. Numbers (profiles, averages, rates, standard deviations) are correct and identical wherever the same quantity is computed twice.
4. Every failure path produces an actionable message and leaves files unchanged.

**In scope:** all 16 modules, the control panels, the 12 target workbooks, `Term01Guidance.xlsx`, `StreamPreferences01.xlsx`, `OrientationResults01.xlsx`, `Term01Results.xlsx`, Examen output, analysis-builder output.

**Out of scope:** Excel/Windows defects, the national platform's export format beyond what the code validates, performance beyond section 8.

## 2. Test levels and strategy

| Level | What | How |
|---|---|---|
| L1 Unit-style | Pure helpers: `ShareCount*`, `NormalizeMark`, `TryBirthDate`, `NameKey`, `Allowed`, `Compat`, `CalcColStat` | Call from the Immediate window in a development workbook, or a throw-away `Test_*` module that is **not committed** |
| L2 Module | One `Run_*` procedure against fixtures | Run from the VBA editor, inspect output workbook |
| L3 Workflow | Chains: Transfer -> Wishes -> Orientation -> Export; Collect -> Distribute -> Clear; Build_All | Run through the panel buttons |
| L4 Safety | Failure injection (open/read-only/missing/protected files) | Manual set-up per case |
| L5 Regression | Fixed expected outputs on a golden fixture | Compare output workbooks to stored expected values |

Prefer **oracle by independent calculation**: compute expected values in a separate scratch workbook or script, not by running the module under test.

### 4.2 Generating a guidance fixture

This script writes a science `Data` table (A2, 21 columns) with random but seeded values and correct profile formulas. Adapt the seed and N per fixture. Header texts are placeholders; orientation reads by column position.

```python
# pip install openpyxl
import random, datetime
from openpyxl import Workbook
from openpyxl.worksheet.table import Table

random.seed(2026)
N = 50
HEAD = ["No","Name","Birth","Sex","Repeat","Arabic","Math","Physics","NatSci",
        "HistGeo","Info","Tech","Average","Section","Wish1","Wish2",
        "P_Math","P_Tech","P_Exp","P_Mgmt","Decision"]
WISH = ["رياضيات","تقني رياضي","علوم تجريبية","تسيير واقتصاد"]
wb = Workbook(); ws = wb.active; ws.title = "Data"
ws.append([None]*21)                      # row 1 (title row)
ws.append(HEAD)                           # row 2 (table header)
r2 = lambda x: round(x + 1e-9, 2)
for i in range(1, N+1):
    m = lambda: r2(random.uniform(4, 19))
    ar, ma, ph, ns, hg, inf, te = (m() for _ in range(7))
    avg = r2((ar+ma+ph+ns+hg+inf+te)/7)
    born = datetime.date(random.choice([2009, 2010, 2010, 2011]),
                         random.randint(1, 12), random.randint(1, 28))
    ws.append([i, f"Pupil {i:03d}", born, random.choice(["ذكر","أنثى"]),
               random.choice(["", "", "", "نعم"]), ar, ma, ph, ns, hg, inf, te, avg, 1,
               random.choice(WISH), random.choice(WISH),
               r2((ma*6+ph*4+ar)/11), r2((te*4+ma*3+ph*3+ar)/11),
               r2((ns*4+ma*3+ph*3+ar)/11), r2((hg*4+ma*4+inf+ar*2)/11), None])
t = Table(displayName="Data", ref=f"A2:U{N+2}")
ws.add_table(t)
wb.save("Term01Guidance.xlsx")
```

Edit rows by hand to create the specific boundary pupils listed in section 6.5. A `.xlsx` created this way contains no Excel-created protection; protect sheets manually if a case needs it.

## 5. Entry and exit criteria

**Entry:** modules imported without compile errors (**Debug > Compile VBAProject** clean); ASCII check passes; fixtures prepared; a clean working folder per run.

**Exit (release gate):**

- All **Critical** cases pass in E1; all **High** cases pass or have an accepted, documented deviation.
- No test left any file modified when the case expects "unchanged" (compare hashes before/after).
- Section 7 regression results recorded (expected current behaviour for open limitations, or fixed behaviour once corrected).
- `changelog.md` updated; behaviour changes reviewed against section 6.5.

Priorities: **C** Critical, **H** High, **M** Medium.

## 9. Execution and reporting

1. Create a clean working folder per run; copy fixtures in; record the Excel build number.
2. Record hashes of all fixture files before the run (`Get-FileHash`).
3. Execute cases; for each record **Pass / Fail / Explore-note**, the message text shown, and the hash comparison where relevant.
4. Open an issue for each failure with the case ID, steps, and a synthetic reproduction. Do not attach real data.
5. Store the results table in the pull request or release notes.
